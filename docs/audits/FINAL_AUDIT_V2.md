日期：2026-09-28。本文件是对 [FINAL_AUDIT.md](FINAL_AUDIT.md) 的**增量复验**，不是重写历史验收记录；未受本轮修改影响的检测、对齐、SFace、模板聚合、跟踪、数据库、选样、实验和限制仍以原报告为准。只修改了旧 CLI 阈值扫描及其窄范围测试。

## 1. 复验范围与原结论

V1 的唯一 Critical Issue 是 `operating_point.py:select_operating_point` 对 margin 边界直接做浮点 `>=`，与生产系统和主要研究路径使用的 `decision.py:accept_identity` 不一致。V1 因此给出 `NEEDS FIX`。本轮按 [FIX_REPORT.md](FIX_REPORT.md) 记录完成了最小修复；没有实施 `REFACTOR_PLAN.md` 中待批准的保守重构，也没有改动历史实验产物。

## 2. Critical Issue 复验

**已解决。** 旧 CLI 扫描现在直接调用 `accept_identity`，没有复制 `1e-12` 容差或另造接受规则。`best=0.275`、`second=0.315`、`margin=0.04` 时，旧 CLI 修复前选 `1e-8`，修复后选 `0.275`；生产接受函数返回 True，研究 `selection.decide` 返回已知身份，研究 validation 标定也得到 `0.275/0.04`。略高于边界可接受；低于边界并超过容差则仍拒绝。单身份不要求第二名间隔，最佳距离阈值仍含等号。

候选阈值集合、CLI 返回字段、metric、默认配置、线上识别及 `face_research` 的实验路径未改。**本轮未发现新的 Critical Issue 或 Major algorithm issue。** 应将 V1 的“Open-set Decision：NEEDS FIX”改判为 **PASS**；V1 第 2 节的缺陷保留作为历史发现，而非当前未解决事项。
