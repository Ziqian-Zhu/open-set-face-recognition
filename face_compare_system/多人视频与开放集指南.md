# 多人视频、开放集与向量库

这是操作/实验说明，不是课程报告。当前新增能力可以运行，但真人准确率、复杂交叉遮挡效果尚未实测；活体检测未实现。

## 1. 桌面演示

先关闭旧程序，双击“启动人脸识别.command”，或执行：

```bash
cd face_compare_system  # 从仓库根目录执行
.venv-ui/bin/python main.py
```

- “开启摄像头”：电脑内置相机，支持多人独立确认。
- “打开视频”：选择自己的本地视频，不开启相机，视频不镜像。
- “视频轨迹”：显示每条轨迹的编号、确认身份、未知、质量拒绝、歧义或冲突状态。
- 轨迹关联使用SFace外观距离和位置门禁；近似打平时不继承旧身份。漏检/低质量后需要重新积累投票。两条轨迹认成同一身份时暂停确认。
- 默认最多32条活动轨迹，超出容量的脸明确标注，不伪装成已确认。CPU是否能实时处理多个人仍依赖硬件和画面。
- 录入仍要求单人，以免模板混入。

## 2. SQLite向量存储

默认SFace配置使用SQLite；LBPH保留files后端。启动会一次性复制导入原同目录JSON库，不修改原照片、向量或JSON。导入失败回滚，不能发布半批人员；重启不会从旧JSON复活已经删除的人员。

`vectors.sqlite3`保存人员、128维float32向量、质量信息、模型签名、可选JPEG图像和软删除归档。精确余弦检索矩阵由同一事务快照重建，按最近至多3个模板的中位数聚合到身份；搜索所有身份，保留真实第二候选用于歧义拒绝。未引入FAISS/ANN，不宣称十万级实时性能。

SQLite事务覆盖服务层身份一致性检查与写入；读端检测revision刷新缓存。软删除与恢复也更新revision，工作线程会清除旧投票。模板不是加密存储，不应公开上传数据库、原文件、日志或视频。

迁移后不得继续用旧程序写people.json。系统会检测旧JSON变化并拒绝静默覆盖，需要人工核对，不能通过删掉元数据绕过。

软删除保留SQLite内部原记录，archives/people-*.json只是恢复索引，必须连同数据库保留。恢复命令：

```bash
.venv-ui/bin/python -m face_compare.cli restore data_sface/archives/people-实际编号.json
```

已有同名人员时整批拒绝恢复。完整备份应在程序退出后复制整个data_sface目录（包含SQLite相关文件），不要只复制恢复JSON。

## 3. 逐帧导出

```bash
.venv-ui/bin/python -m face_compare.cli video /绝对路径/test.mp4 --every 3 --output evaluation_results/video-01.jsonl
```

使用当前人员库，按原视频帧号/fps时间推进，逐个处理被选中的帧，不模拟实时丢帧。输出metadata、frame、最终summary；每张脸含框、轨迹、确认状态、身份、距离、质量。新版 `video-dual-decision-v2` 额外保留 `single_frame` 原始身份判定，用于同一次处理结果的时序配对。缺少summary表示执行中断；EOF也可能是解码中断，应检查帧数。可用`--max-frames 300`限制读取帧数。

输出中处理耗时不等于视频首次身份确认时间，更不能由此声称真实相机FPS。无真值标注时accuracy为null。

## 4. 标注视频评测

参考`video_truth.example.json`，为导出里的全部frame记录填写真值；无人帧写`faces:[]`。subject是视频内真实人物编号，不同未知人员也要不同编号；已录入label填姓名，未知label为null。box使用原视频像素[x,y,width,height]。

标签不可省略，否则报错而不是默认为未知。新版校验还要求帧号、时间戳、耗时、框、轨迹ID有效，导出metadata中的fps/every与summary中的解码/分析帧数必须与全部记录一致。不能同时从预测和真值中删除困难帧来提高结果；旧文件缺完整元数据时不能提供同等级检查，输入哈希也不等于不可篡改证明。

```bash
.venv-ui/bin/python -m face_compare.cli evaluate-video evaluation_results/video-01.jsonl /绝对路径/truth.json --output evaluation_results/video-score-01.json
```

工具用IoU≥0.5贪心一对一匹配，报告检出率、未匹配检测、轨迹编号切换、已知识别/误认/拒绝、未知误接受及每段首次正确确认时间。`scene` 字段统计同时出现多张脸的帧数与峰值。每段（同一人连续出现的 episode）统计出现/检出/可识别/正确帧数、误接和误认帧数，以及**连续可识别输出**中的身份跳变；另有包含待确认和漏检的全部状态切换，避免用少输出伪装稳定。未确认片段单独保留，不能只对成功片段取平均。此实现不是完整MOTChallenge评价；同一视频连续帧高度相关，帧比例置信区间不能解释成人员级独立试验区间。

`subjects` / `subject_summary` 合并同一人物的重现片段，给按身份等权的macro比例，不让长轨迹决定整体结果。真值顶层可提供真实`session_id`，缺失则保持null；程序不自动把相机视角或连续片段当新会话，也不能验证提供的批次是否真的独立。新增身份统计不附假设独立的置信区间。

### 单帧／多帧配对评估

```bash
.venv-ui/bin/python -m face_compare.cli evaluate-temporal evaluation_results/video-01.jsonl /绝对路径/truth.json --output evaluation_results/temporal-score-01.json
```

只读取导出和真值，不创建/修改人员库。比较共享检测、匹配与轨迹关联的 `single_frame` 和 stable 输出，报告已知正确得失、未知误接增减、输出覆盖、首次确认延迟和状态切换；时序侧包含同身份冲突抑制，不是完整 tracking 算法消融。输入哈希保存在结果里。旧导出缺 `single_frame` 时拒绝配对，不从稳定结果反推原始判定；仍可单独 `evaluate-video`。两组耗时来自同一次处理，不用来比较时序额外开销。合成轨迹回归已通过，但真实运动视频收益尚未验证。

## 5. Open-set验证集阈值选择

性能评估另有研究入口 `face_research.video_benchmark`，使用**临时合成向量库**，不使用这里的当前人员库。它测正式服务/跟踪调用的六阶段耗时、解码和处理吞吐率，不计算识别准确率；不能把它的FPS当相机/GUI FPS。预热后重建tracker，原始时延和哈希完整输出。命令、无需新视频数据的合成连通性检查及限制见[视频性能入口](../face_research/VIDEO_VALIDATION_STATUS.md)。

先按`evaluation.example.json`制作独立录入/验证图片清单，标记`split:validation`，至少包含已知及未知人员：

```bash
.venv-ui/bin/python -m face_compare.cli evaluate /绝对路径/validation.json --output evaluation_results/validation-01.json
.venv-ui/bin/python -m face_compare.cli select-threshold evaluation_results/validation-01.json --target-fpir 0.01 --output evaluation_results/operating-point-01.json
```

固定身份间隔，扫描距离阈值，在可用未知人脸的经验误接受比例不超过目标时，选择已知正确率更高的阈值。输出曲线、计数、Wilson区间和建议config补丁，不自动改配置。小样本0次误认不代表真实风险为0或已经达到总体1%的指标。

应用建议后，用另一次采集的`split:test`清单评估；test报告被工具禁止用于选阈值。未知验证人员尽量与最终测试人员分开；同一次视频连拍不能当成独立样本。阈值工具优化的是静态搜索，不是视频投票或活体防伪。

## 6. 回归与复现

```bash
.venv-ui/bin/python -m pytest -q
.venv-ui/bin/python scripts/check_startup.py
.venv-ui/bin/python scripts/check_ui.py
.venv-ui/bin/python scripts/smoke_models.py
.venv-ui/bin/python scripts/smoke_video.py
```

后两个脚本依赖已有OpenCV公开测试图`.qa/public_samples/`。双人视频检查使用重复静态图片并放宽测试质量门禁，仅检查模型、SQLite、视频解码、两条轨迹和已知/未知输出连通，不是准确率或真实运动测试，不修改正式配置。

本轮真人采集已取消，当前通过公开图实验、静态/合成性能基准和合成轨迹回归推进；实际公开多人运动视频仍须取得合法数据及独立录入依据才能验证，不将它列为已通过。最新全套449项回归；LTFT作者标注预检及下载/协议限制见[公开视频状态](../face_research/VIDEO_VALIDATION_STATUS.md)。近似索引由基准和业务时延需求决定，活体模块不在本轮范围。
