## 检查发现与处理

| 原问题 | 已落实的处理 |
|---|---|
| 原始纹理描述对姿态和裁剪偏差敏感，未做人脸对齐 | 默认YuNet五点检测＋112×112对齐＋SFace单位特征，LBP单独保留 |
| 已采样后修改姓名可能把照片存给另一个人 | 会话绑定姓名，首张后禁用姓名框，服务检查身份一致性 |
| 连点重复照可能让模板数虚增 | 0.8秒间隔、32×32灰度缩略图平均绝对差去重、采集缩略图反馈 |
| 刚换人时旧的多数票可能仍显示上一人的姓名 | 当前帧/最近两帧必须支持赢家，另用位置/特征/时间连续性复位 |
| 质量不足或多人时仍沿用主脸历史 | 清空确认历史，显示当前实际状态 |
| 主线程运行检测导致UI卡顿 | 独立推理线程，最多1帧待处理，按设备代次和时间丢弃过期输出 |
| 数据写到一半失败会污染内存元数据 | 在独立副本准备元数据，全部成功提交后更新内存；批次先校验特征 |
| 日志写失败可能使已成功保存看起来失败 | 日志失败单独记录告警，不撤销或伪装已成功的录入 |
| 旧进程持有的索引可能把删掉的人重新写入 | 写入前检查索引版本，过期时要求重启；UI内可恢复移出并即时刷新 |
| 缺特征文件静默跳过 | 明确报错，并检查特征维度、有限值和模型签名 |
| 库内阈值校准与现场性能容易混淆 | 深度模式固定初始工作点，用独立验证集/测试集评估；不根据录入照自校准 |
| 相机1误标为外置 | 默认改0，并使用“默认摄像头”中性标签，仍需看预览确认设备 |
