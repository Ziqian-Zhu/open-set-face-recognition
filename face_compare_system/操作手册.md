# 人脸比对系统操作手册（升级版）

## 启动和选择相机

关闭旧窗口，在终端执行：

```bash
cd face_compare_system  # 从仓库根目录执行
.venv-ui/bin/python main.py
```

也可双击项目目录下的“启动人脸识别.command”。当前Mac已配置Python 3.12 / Tk 9的独立`.venv-ui`，旧`.venv`及人员库原样保留。使用旧命令`.venv/bin/python main.py`时，会自动切换到兼容环境，避免继续使用系统Tk 8.5。新环境依赖本机已有的Python运行时；若以后删除或移动该运行时，需要用带Tk 8.6+的Python重建`.venv-ui`并安装requirements.txt。

启动后进入“FACE / STUDIO · 人脸识别工作台”：左侧为深色实时视窗，画面下方显示识别结果；右侧为设备连接，以及“录入人员 / 已保存人员”两个页签。算法名称“YuNet + 五点对齐 + SFace”显示在画面下方。

Mac版启动/刷新只读取系统设备名称，不试开镜头，并过滤iPhone连续互通及桌上视角相机。默认优先选择带“电脑内置”的设备；本机核查为“FaceTime高清摄像头 [1]”，编号可能随设备变化，不应固定认为0号是内置相机。点“开启摄像头，开始识别”才打开选定镜头。画面仰拍时可调整屏幕角度；程序仅左右镜像，不旋转视角。窗口较小时可在右侧滚动，ESC停止相机并恢复启动引导画面。

没有发现电脑摄像头时，启动按钮会禁用，不会猜编号或改用手机。设备成功打开也不等于已收到画面；连续5次读取失败会停止连接。请关闭其他占用相机的应用，确认运行程序的终端/Python已获系统相机权限，然后刷新重试。

## 录入

1. 在右侧“录入人员”页签输入姓名，画面只留一人，等待质量合格。
2. 点“采集一张”，看到第1张缩略图及1/5。姓名自动锁定。
3. 按提示轻微左右转头、微笑、恢复正脸。停稳再采，两次至少间隔0.8秒。
4. 收集5张（新人员最少3张），确认都是同一个人，再点“保存入库”。
5. 保存后姓名和计数清空，依次录入另外两人。

“几乎重复”表示图像变化太小；“可能混入其他人”表示特征不一致或姿态过大，先改善光线和姿态。采错或换人时点“清空未保存样本（不删除已保存人员）”。

新模式使用data_sface/，旧LBP库data/保留，需要在新模式重新录入。

## 比对与删除重录

录完后先离开画面，再重新进入，等待“正在确认”变成姓名。换人、多个人、质量不足会清空旧确认。让未录入的人测试未知结果。匹配分不是概率，深度模式“阈值说明”只展示当前工作点，不以录入照自动调参。

删除已经保存的人员：

1. 点窗口右上角“管理 / 删除已保存人员”，或者右侧“已保存人员”页签。
2. 在列表中点要删除的姓名，上方红色按钮会显示“删除「姓名」”。
3. 点击红色按钮，核对确认框里的姓名和样本数，再确认删除。点取消不会改动数据。

删除立即生效，不必重启；其他人员及尚未保存的采集样本不受影响。删除后可以重新录入。当前库名称显示在页签底部，旧LBPH库不在SFace列表中。

人员较多时可用列表滚动条，也可点“展开列表”；删除全部人员入口只在展开窗口中提供，并需单独确认。原索引归档到当前库archives/，原照片和特征保留，因此是从识别库移除，不是永久擦除。

新SQLite库恢复归档：关闭旧版程序，运行 `.venv-ui/bin/python -m face_compare.cli restore data_sface/archives/people-实际编号.json`。同名人员冲突时会拒绝恢复，不覆盖现有人员。归档JSON只是恢复索引，原照片/向量仍在SQLite中，不能单独当完整备份，更不能复制为people.json。旧LBPH的files库仍使用旧JSON恢复方法，切勿混用。

## 多人和视频（新增）

识别时可以多人同框，每张脸独立显示T编号；右侧“视频轨迹”列出身份和状态。T编号只代表轨迹，不代表永久身份。交叉、遮挡、画质不足或身份冲突时会重新确认。录入仍要求画面恰好一人。

点击设备卡中的“打开视频”选择本地文件，无需相机。相机预览仍左右镜像，视频保持原方向。点击“停止视频”或ESC结束；文件结束或解码失败时停止回放，不自动改用摄像头。

第一次运行新版SFace配置时会复制导入旧库有效记录到data_sface/vectors.sqlite3，原JSON与照片文件保留。请先关闭旧窗口，迁移后只用新版；检测到旧JSON被其他程序修改时会停止操作，避免静默覆盖。

## 验证准确性

至少3名已录入人员各拍10次新画面，另找至少3名未知人员各拍10次。分正常光、轻微转头、暗光、眼镜等场景，分别记录姓名正确、认错、未知、无人脸、质量失败。

使用evaluation.example.json按真实路径准备gallery和probes，未知label为null。路径相对于清单文件。运行：

```bash
python -m face_compare.cli evaluate evaluation.example.json --output evaluation_results/test-01.json
```

调参数用validation，最终用另采的test。工具不覆盖已有实验结果，也不修改当前人员库。详细字段见README。

## 常见问题

- 动画：视窗右上状态环只提示真实连接/分析状态；采集进度与保存反馈有短过渡。底部勾选“减少动画”即可关闭，不影响识别。保存成功改为底部文字确认和样本数更新，不再弹出成功对话框；保存失败仍明确提示。
- 视频节奏：新版按累计播放期限调度，避免30ms刷新把30FPS文件拖成约17FPS；跟踪使用视频帧序号/FPS时间，结果过期仍使用本机时钟。超过1秒的卡顿会重新设定播放期限、保留后续帧，不宣称复杂视频永远实时。变帧率文件仍按OpenCV报告的FPS近似计时。
- 未检测到：正对镜头、改善正面光线，不要大幅侧身。
- 模糊：重启新版后，SFace界面显示“分区细节 / 门槛”，不再用旧的原始方差55一票否决。擦镜头、正面补光、停稳后再采；低清图片放大不能恢复细节。新分数不是概率，也不与旧“清晰度42”在同一量纲。
- 摘掉眼镜无法采集：先区分画质拒绝与身份一致性拒绝。画质弹窗会显示细节分数和门槛，失败指标记录在 `logs/events.jsonl` 的 `enrollment_quality_rejected` 事件（不新增保存失败照片或向量）。请保留截图和指标，不要删除身份或一味降低匹配阈值。戴/不戴眼镜均应追加到同一姓名。
- 距离过远：靠近屏幕，让脸占更大面积。
- 姓名不能编辑：已有待保存照片，保存或清空本次采集后才能换人。
- 库被另一个程序修改：关掉旧实例再重启，只开一个程序。
- 缺模型：运行 `.venv/bin/python scripts/download_models.py`。
- 日志不可写：修复目录写权限；日志错误不会把已保存样本变成失败，不要因此重复保存。
